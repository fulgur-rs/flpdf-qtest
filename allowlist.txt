# flpdf-qtest allowlist
#
# Each non-empty, non-comment line declares an acceptance-test entry that
# MUST pass on CI. Format:
#
#   <test-stem>[:<subtest-name>]
#
# Examples:
#   deterministic-id                    # every subtest in deterministic-id.test must pass
#   arg-parsing:required argument       # only this single subtest is required to pass
#
# Semantics enforced by scripts/verify-allowlist.py:
#
#   allowlist PASS    → expected, verdict OK
#   allowlist FAIL    → REGRESSION, verdict FAIL, plotted on the trend chart
#   allowlist not run → verdict FAIL (typo, deleted upstream test, etc.)
#   non-allowlist PASS → allowlist-candidate (surfaced in qtest-summary.md)
#   non-allowlist FAIL → informational
#
# Verdict never gates CI: verify-allowlist.py exits 0 on FAIL as well, so a
# flpdf-side regression does not block the nightly metrics upload. The FAIL
# is instead visible on the trend chart as a bump in the `regressions`
# series. Only real errors (unparseable log, parse drift) exit non-zero.
#
# Policy: only add an entry AFTER the implementation in flpdf actually makes
# it pass. The allowlist is the public record of qpdf-CLI compatibility
# claims, not a wishlist.
